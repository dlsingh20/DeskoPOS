# Reports

Open **☰ → Reports** (`/reports`). It needs the `reports.view` permission (Managers and Administrators). The older charts dashboard is still available as **Analytics** (`/analytics`).

## How it works

Reports are calculated in the browser from the same closed bills that History uses:

- `HistoryService.getClosedOrders`
- `classifyBill`, which applies the bill, payment and collection rules

So the numbers always match History. The definitions are in `src/utils/reportUtils.js` (tests: `reportUtils.test.js`) and the screen is `src/components/reporting/ReportsView.jsx`.

### Adding a report

Add an entry to `REPORTS`:

```js
{ key, group, label, description, compute(bills, ctx) => ({ columns, rows, totals, kpis?, notes? }), filters: [...], status }
```

- **Column types:** `text`, `number`, `money`, `percent`, `date`, `datetime`.
- **Totals:** `totals: true` adds up the `money` and `number` columns. Rows with `excluded: true` are left out.
- **Free with every report:** the screen, sorting, totals row and Excel export.

## Reports included

| Group | Report | Notes |
|---|---|---|
| Sales | Sales summary | Bills, gross, discounts, net, service charge, tax, total, average bill, collections, order types, cancellations |
| Sales | Day-wise sales | One row per day (restaurant time zone) with the payment split |
| Sales | Bill-wise sales | Every bill. Cancelled and refunded bills are greyed out and not in the totals |
| Sales | Hourly sales | By order hour |
| Payments | Payment modes | Each mode, with Paytm / PhonePe / UPI separate; awaiting confirmation, refunds and unpaid credit listed separately |
| Payments | Pending & credit bills | Oldest first, with age in days |
| Items | Item-wise sales | Quantity, value, average price and share; category filter |
| Items | Category-wise sales | |
| Staff & tables | Server / waiter performance | Bills, sales, average bill, tips (from the settlement notes) |
| Staff & tables | Table-wise sales | Bills, sales, average time from order to close |
| Exceptions | Discounts | Discount %, reason, given by, approved by |
| Exceptions | Cancellations & voids | Cancelled and refunded bills, cancelled items, manager-approved voids |
| Tax | Tax summary | Day-wise taxable value and tax, split into the components from the print settings (e.g. CGST/SGST) |

**Filters** (each report shows only the ones that apply):

- Bill status (sales, fully settled, pending, cancelled, refunded, all)
- Bill type, payment mode, table, server, item category
- Search by bill number, amount or customer

**Periods:**

- Today, Yesterday
- Last 7 days and Last 30 days (both end yesterday)
- This week and Last week (Monday start)
- This month, Last month
- Custom date and time

**Excel export:** two sheets, Report Info (period, time zone, currency, filters, generated by, key figures, notes) and the report itself with a totals row.

## Limits and backend work

- **Volume:** all bills in the period are loaded into the browser, up to 5,000 orders, after which a warning is shown. For long periods or large outlets, add server-side report endpoints with the same filters, e.g. `GET /pos/api/reports/<name>/?from&to&restaurant_id&type&status&payment&table&server`. The existing `/reports/*` endpoints have no documented parameters or definitions, so they aren't used here.
- **Item amounts** are before bill discounts and tax. Item-level discount allocation and item tax rates need server support.
- **Covers / guest count:** orders have no guest-count field, so there's no per-cover report.
- **Categories** come from the current menu; deleted items show "Uncategorised". Snapshot the category on `OrderItem`.
- **Tips** and **void approvals** are read from notes. Proper `tip` fields and an audit log would make these reports exact (see the backend notes in `docs/FINE_DINE_BACKEND_REQUIREMENTS.md` and `docs/USERS_AND_ROLES.md`).
- **Not built yet:** shift / cash-counter close (X/Z) report, multi-outlet comparison, purchase and inventory reports, scheduled email reports.
